picassobackend

The server side of PickUsAll

A C++20 server built on oat++ for PickUsAll (Picasso), a KMP / Compose client for gaming-focused friend groups. Each conversation lives authoritatively on exactly one instance — self-hosted or managed — and clients hold a WebSocket connection to every server they have added.

  • oat++ 1.3.0

What it does

Chat source of truth

The client's local store is a cache; this server owns the real history for the conversations created on it.

Call signaling only

Audio never touches the server. It resolves who is in a conversation and online, then forwards opaque SDP and ICE payloads — media is a P2P mesh between participants.

Steam login verification

Steam Web API calls stay on the client. The server's Steam-facing job is validating OpenID assertions, which a client cannot do for itself.

Roadmap

  • Skeleton Modules, env config, real bind errors, one JSON error handler. Done
  • WS transport SDP/ICE/hangup frames relay end to end; chat and call-invite frames are still parsed and logged only. In progress
  • Auth A temporary stand-in trusts any numeric bearer token as the steamId, unblocking testing. Real Steam OpenID verification isn't built yet. In progress
  • Storage Schema migrations and Postgres repositories are wired in and run on startup; chat/call services don't call them yet, so nothing is written through the API. In progress
  • RTC signaling Forwarding works, but relays to any steamId with no conversation-membership check — an open relay until that guard lands. Planned

Running it

The binary binds 0.0.0.0:8000 by default; PICASSO_BIND and PICASSO_PORT move it. GET /ping answers pong with an X-Service-Status: Healthy header — endpoints that are not built yet reply with a uniform 501 naming the roadmap step they are waiting on.

Startup now requires a reachable Postgres at PICASSO_DB_DSN: it applies the schema migration and connects the repositories before the server serves any traffic. A docker-compose.yaml in the repository brings up Postgres, the backend, and a monitoring stack (Caddy, Prometheus, Grafana) together — see the docs.
