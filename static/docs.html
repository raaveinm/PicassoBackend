Variables, builds, usage

The environment variables the server reads at startup, how to build it from a clean checkout, and the endpoints that answer something real today. For the full design rationale — wire protocol, layering rules, roadmap — see CLAUDE.md in the repository.

Environment variables

All of them are optional — an unset variable falls back to the default shown below.

Variable Default Meaning
PICASSO_BIND 0.0.0.0 Address the HTTP/WS listener binds to.
PICASSO_PORT 8000 Listener port. Must parse as an integer in 1..65535, or startup fails.
PICASSO_DB_DSN empty Postgres connection string. Read into Config already; nothing connects with it yet — storage is still stubbed.
PICASSO_PUBLIC_URL http://127.0.0.1:8000 Base URL this instance is reachable at, used for Steam OpenID return addresses.
PICASSO_LOG_LEVEL info Stored on Config; not wired to the logger yet.

Build

Verified configuration: Linux, g++-11, Ninja Multi-Config, Conan from a repo-local .venv. The Conan profile is derived from the compiler you pass below.

First-time bootstrap

cmake --preset conan-release cannot be used on a clean checkout — that preset file is generated by Conan's toolchain, which only runs once configure has already started. Bootstrap with a direct invocation once: 

cmake -S . -B build -G "Ninja Multi-Config" \
    -DCMAKE_C_COMPILER=/usr/bin/gcc-11 \
    -DCMAKE_CXX_COMPILER=/usr/bin/g++-11 \
    -DCMAKE_BUILD_TYPE=Release

Every build after that

The build directory is multi-config — binaries land in build/<Config>/, and a bare ninja in build/ does not necessarily build the config you expect. Always pass --config explicitly: 

cmake --build build --config Release

Docker

The repository's Dockerfile reproduces the same toolchain from a clean Ubuntu 22.04 base:

docker build -t picassobackend .
docker run --rm -p 8000:8000 picassobackend

Usage

Endpoints that are not implemented yet answer a uniform 501 naming the roadmap step they are waiting on, instead of a generic error.

Request Status Response
GET /ping 200 pong, with header X-Service-Status: Healthy.
GET / 200 Serves static/index.html.
GET /docs 200 This page (static/docs.html).
GET /ws, no bearer token 401 Rejected before the upgrade.
GET /ws, Authorization: Bearer <uint64> 101 Switches protocols. The token is taken as the literal steamId with no verification — a temporary stand-in ahead of real Steam auth, not safe for a public network.
Any unimplemented endpoint 501 {"status":501,...,"message":"service: ... not implemented yet (roadmap step N: ...)"}

WebSocket frames

One connection per client per server, carrying both chat and RTC signaling as an EnvelopeDto. sdp_offer, sdp_answer, ice_candidate, and call_hangup are relayed end to end today; chat_message and call_invite are parsed and logged only. See CLAUDE.md's "Wire protocol" table for the full frame list.
